# v1.0.7：战术换弹时序修复

安装包：`build/Auto-Reload-v1.0.7.zip`。运行日志版本：`auto-reload-1.0.7`。

## 行为

确认当前武器与弹药仍满足阈值后，立即清除当前开火并建立一次固定 500 毫秒屏蔽；在屏蔽中等待既有的 80–150 毫秒随机时间，再复核状态、发送 R。保护从首次打断开始计时，包含随机等待，正常情况下发 R 后还剩约 350–420 毫秒。低帧率、输入拒绝等导致首次 R 直到保护结束仍未发送时，取消过期请求，不再自动延长保护。

一次达到阈值至弹药恢复或上下文取消视为同一轮。定期检查和新开火边沿不能反复刷新保护；重试只发 R，不重新压制开火。普通受保护武器最多发送三次 R，沿用 1 秒、2 秒的重试等待，每次另外抽取原有随机延迟。毒矛沿用自身有限重试间隔。逐发装填、逐发下挂、AC-8 机炮及原有站桩、载具排除范围保持不变。

确认原生换弹动作进行中时，取消等待中的重复 R 并暂停重试。动作结束后仍未恢复弹药，可以继续剩余的有限重试；这不会重开半秒保护。切枪、换座、人物失效、失焦、设置取消和退出沿用清理逻辑，设置取消也会丢弃整轮状态。

## 换弹状态与诊断

当前 build 25480438 原生 `0x776010` 读取有效 Reload 配置 `+4` 的动作 ID，并与持有者正在执行的 Ability 匹配。实现只读该路径：Reload 实体覆盖位于 manager `+0x60/+0xa0`、配置步长 80；模板走 owner `+0xf12800` 的 498 项资源表；玩家 Ability 步长 `0xe0`，活动标志 `+0x10`。读取前核对代码签名，读取中核对实体与指针，结束时沿用快照复读。布局或身份不能确认时不把候选字段视为已开始装填，仍采用有限重试。

新增日志：

- `DEBUG_FIRE_INTERRUPT_BEGIN ... phase=threshold`：阈值时启动，包含 elapsed。
- `INPUT ... name=FIRE_NATIVE`：游戏合并 FIRE 状态；原 `FIRE` 仍为 Windows 左键与游戏 FIRE 的组合。
- `DEBUG_FIRE_BLOCK_STATE`：保护期间约每 0.1 秒回读 Windows 左键、合并 FIRE、原生屏蔽 mode 和剩余毫秒。Windows 状态也会受到模拟松键影响，不能当成独立硬件采样。
- `RELOAD_DELAY_QUEUED`：增加时间、排队时弹匣与膛内标识；`RELOAD_REQUEST` 改用发送前最新快照的弹药。
- `RELOAD_ACTION_CONFIRMED`：原生装填动作已匹配，不等同于换弹动画全部结束。

日志保持由已有菜单开关控制。随机采样器、拟合平均值与方差、GUID、菜单保存值不变。

## 验证与使用

按用户要求仅做相关路径的离线检查：提前保护、80/150 毫秒边界、500 毫秒到期、松开再按、失败请求、重试不续期、原生状态抑制重试、排除与取消、换弹状态身份及动作匹配，以及完整入口语法和安装包内容。

一次实机只读快照确认 AR-59 的新读取路径可用：`reload_state_verified=true`、换弹动作 ID `2745`、当前 `reload_action_active=false`；该快照不包含实际自动输入测试。没有部署新包，也没有向游戏发送测试输入。

替换旧包、部署并重启游戏后，日志应显示 `auto-reload-1.0.7`。固定半秒用于保护换弹启动，之后开火控制权归还玩家；不保证在持续重新开火时仍完成整个装填动作，也无法撤回游戏已经提交执行的射击。
