# v1.0.8：站桩触发、备弹耗尽与切枪清理修复

安装包：`build/Auto-Reload-v1.0.8.zip`。运行日志版本：`auto-reload-1.0.8`。

后续用户实测确认站桩和备弹两项修复生效；切枪仍可能因松 R 生成原生短按事件而串线，补修见 [v1.0.9](RELEASE_1.0.9.md)。

## 站桩武器

原判断允许开火按下沿和首次观察到空仓发生在同一更新帧，打出最后一发的点击可能被当作空仓后的再次点击。现在按下沿保存武器身份及更新帧，只接受首次确认空仓之后、后续更新帧出现的新按下沿。切枪或上下文变化同时清除旧边沿。

GR-8、MG-43 等既有站桩名单，以及 AC-8 关闭战术换弹时的限制沿用该判断。正常的最后一枪或持续按住开火不会自动授权站桩换弹；空仓后的新点击才会排队自动 R。

## 备弹检查

复用三倍备弹模组已核对的只读字段：Magazine 运行时 `+0x50`、每项 12 字节；Rounds `+0x58`、每项 20 字节；Heat `+0x58`、每项 12 字节。当前备弹均位于记录开头，Heat 即已有 `heat_spares`。

没有原生自身备弹容量的当前三号位主武器，另检查本地角色库存中实际携带的背包。核对完整 Item/ResourceCounter 资源表、原生读取签名、背包身份和组件身份后，读取类别 17/18 弹药背包的 ResourceCounter 当前计数。下挂使用其独立弹药组件，不借用三号位背包。

首次触发、逐发续装、定期补发、专用重试和延迟发送均经过共用备弹判断；发送前再次读取。备弹为零或来源无法确认时取消排队和重试，补给后按当前武器规则重新判断。已有载具若没有原生自身备弹池，保持此前已核对的载具换弹规则；有自身备弹池时检查计数。

日志新增 `reserve_verified`、`reserve_count`、`reserve_source`、`reserve_native_max`、`reserve_backpack` 和 `reserve_backpack_class`。

## 武器身份与输入清理

延迟请求、重试计时和已按下的自有 R 都保存原武器身份；身份包含人物、武器实体、资源、槽位、当前主枪/下挂选择、弹药路径及使用的背包身份。每次重试与实际发送前都检查该身份，旧请求不转移到新武器。

发现切枪、切换下挂、背包更换或上下文失效后，立即尝试释放模组持有的 R，无需等满原来的 80 毫秒；释放失败时保留所有权并在后续帧继续释放，期间不能注入新的 R。保留释放帧与下一次按下帧分离的规则。已经被游戏消费的按键无法撤回。

## 打包与实测

GUID 和菜单保存 ID 沿用旧版。换弹阈值、80–150 毫秒随机等待及原有半秒开火保护参数保持原样。

本次按用户要求只修改代码和重新打包，未运行额外测试、未部署安装包、未向游戏发送输入。实际行为由用户替换旧包、部署并重启游戏后测试。
