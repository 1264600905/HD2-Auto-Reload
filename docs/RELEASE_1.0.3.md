# v1.0.3：随机换弹延迟测试版

安装包：`build/Auto-Reload-v1.0.3.zip`。

## 改动

普通空仓、战术换弹、逐发连续装填、下挂、过热更换、载具换弹以及自动重试，统一在模拟按下 R 之前加入一次 **80–150 毫秒**整数随机等待。逐发补弹的每次自动按键独立抽样，同一个待发送请求不会逐帧重抽，也不会在普通与连续补弹路径中重复排队。

分布沿用用户按键间隔样本拟合的平均值 **133.5821611111111 毫秒**、总体方差 **306.24582071126537 毫秒²**。这是随机抽取值的统计目标，并不意味着任意少量抽取都恰好等于目标。中位数和完整分布没有拟合；中位数仍约为 140 毫秒。

随机状态为本模组私有，每次会话初始化一次，不修改其他模组使用的公共随机状态。等待由游戏更新逐帧处理，不暂停游戏线程。

## 等待期间的处理

- 切枪、更换人物、换座、上下车、失焦、死亡或不再满足补弹条件时，取消旧请求。
- 逐发武器重新开火时取消等待；松开火后，按仍有效的补弹条件重新计时。
- 到期后再次读取最新弹药、人物、武器、座位和输入状态，再发送按键。
- 周期检查和点击触发的请求会保留到延迟结束，不要求到期那一帧再恰好出现周期检查或点击。
- 实际发送成功后才增加已请求状态和重试计数；临时输入拒绝不会反复重抽等待值。
- 应用换弹设置会取消旧等待；仅切换日志不会重置正在等待的换弹。

爆裂铳自动拉栓使用模拟开火动作，保留原设置与时序。本次随机延迟作用于全部自动 R 换弹，手动按键仍由游戏处理。

## 范围说明

**80–150 毫秒约束的是抽取值。** 游戏更新和系统计时存在间隔，实际按键可能比抽取值晚一个帧间隔，临时被输入占用时也可能继续等待。因此不能把离线抽样的平均值、方差当作实际游戏中所有装填耗时的统计结果。

日志开启后：

- `RELOAD_DELAY_QUEUED` 记录抽取值和原因。
- `RELOAD_DELAY_SENT` 同时记录抽取值和实际经过的等待时间。
- 初始化版本为 `auto-reload-1.0.3`。

## 验证

- 新增 20 项定向测试，覆盖两端边界、一次抽样、不同换弹路径、逐发再次抽样、重复排队抑制、状态变化取消、开火优先、发送前重读、临时拒绝、周期与点击触发保留、重试计数和实际更新调用。
- 原有 75 项控制器检查通过，旧弹药策略检查使用零延迟测试条件，将策略验证与新延迟验证分开。
- 菜单设置和爆裂铳拉栓检查通过；设置检查包含真实菜单的保存恢复，使用独立临时目录。
- 对实际生产随机函数进行五组、每组十万次抽样。五十万次均为 80–150 毫秒整数；合并平均值约 **133.589964 毫秒**，方差约 **306.230399 毫秒²**。
- 安装包结构、资源标识、源码一致性、压缩包完整性和完整 Lua 入口语法检查通过。

这些都是独立进程内的离线检查，游戏输入由记录用的替身函数代替；没有向正在运行的游戏发送按键，没有部署或热加载。逐发实际装填手感、不同帧率和真实联机行为交由用户安装后测试。

## 安装

在管理器中导入本包替换旧版，与原有 Bingus Shared Loader 和菜单依赖一起部署，再重启游戏。资源路径和管理器标识沿用，已有菜单保存值继续使用。本版是本地测试包，未发布到远端。
