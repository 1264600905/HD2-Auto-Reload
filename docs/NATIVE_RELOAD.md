# Native reload experiment

The build `25480438` prototype binds the game's reload request at RVA `0x774b60`, not only the ability starter. The original path resolves `WeaponReloadComponent`, checks eligibility, starts the configured ability and performs post-start work. See the [GL-15 investigation](NATIVE_RELOAD_GL15.md) for call-site evidence. The [extracted component schema](https://github.com/shalzuth/HelldiversData/blob/master/data/components/WeaponReloadComponent.json) identifies the per-weapon ability and duration fields.

The experimental package verifies the build and native instruction sites, then reads the selected owned weapon's Reload registry, effective resource or entity-override config, and Ability registry/state. It uses the config's ability ID rather than a GL-15 constant. If no Reload component or valid ability is available, it retains the existing R-input backend. Invalid identities or changed native code latch a fault and stop automatic requests instead of guessing. This avoids a whole-map equality requirement for Reload while retaining the existing Magazine/Rounds/Heat guards.

The same 50 tactical weapon rules remain available. GL-15 uses `basis='total'` and `limit=2`; total means selected magazine plus a chambered round. At two rounds, its non-immediate rule observes the existing click-delay window. Native per-round reloads do not call again merely because time passed: the previous native action must end and ammunition must increase while still inside the tactical window. An unconfirmed request may be retried after eight seconds and a fresh attack click. A returned native call is logged as a request, not animation completion.

Build with `python scripts/build.py --native-reload --enable-tactical-reload --game-dir 'your Steam library/common/Helldivers 2'`. The output `build/Auto-Reload-v0.7.0-native-tactical.zip` shares the ordinary mod GUID. Close the game, replace the previous Auto Reload package, deploy and restart. Keep the default R binding for weapons that use fallback. A non-tactical native package is available by omitting `--enable-tactical-reload`.

The user's installed GL-15-only prototype logged multiple native calls followed by ammunition recovery from empty. This does not yet verify the expanded build, early tactical threshold, other weapon classes, multiplayer or every interruption state. Test first with GL-15 at two total rounds, then one ordinary Magazine weapon, one other Rounds weapon and a replaceable Heat weapon. After each, check `AutoReloadRounds.log` for `NATIVE_RELOAD_CALL_BEGIN`, `RELOAD_REQUEST` and actual ammunition recovery. Unsupported or changed builds fail closed.

A later read-only run of the expanded context reader observed a different equipped Rounds weapon (`51f50d6321f52f3d`) with matching Reload/Ability registries, ability ID `2827`, and an idle action. This validates another weapon's pre-call data path only; that weapon's native reload has not yet been invoked by the new package.

The running build's 498-entry Reload resource table contains all 50 configured tactical weapon resource IDs. This confirms static configuration coverage, not that every equipped instance will pass runtime identity/eligibility checks or complete an in-game reload.
