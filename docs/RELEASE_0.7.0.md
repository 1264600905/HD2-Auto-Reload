# v0.7.0 — 原生换弹实验版

适用 Steam build `25480438`；普通输入包仍保留 `25327279` 的运行时兼容检查。依赖 Bingus Shared Loader v15+ / API 1。所有安装包使用同一 Mod GUID，**只能启用其中一份**。

| 安装包 | 用途 |
| --- | --- |
| `Auto-Reload-v0.7.0-tactical.zip` | 战术阈值与模拟 R；不调用游戏内部换弹函数 |
| `Auto-Reload-v0.7.0.zip` | 仅空仓自动换弹与模拟 R |
| `Auto-Reload-v0.7.0-native-tactical.zip` | 实验性原生换弹优先，并启用战术阈值；无可验证 Reload 组件时回退模拟 R |
| `Auto-Reload-v0.7.0-native.zip` | 实验性原生换弹优先，仅空仓触发 |

同名 `-debug.zip` 包提供详细诊断日志，不改变对应模式的触发规则。推荐先用输入战术包作稳定基线；希望测试内部函数与 GL-15 两发阈值时，选择原生战术包。

## 本版变化

- `25480438` 的运行时 PE 标识、布局签名及 Magazine/Rounds/Heat 完整表经过只读验证；修复了无既存声明时 `SendInput` 初始化失败。
- 原生实验版绑定游戏的换弹请求函数，而不是只调用动画能力。按当前武器的 Reload 有效配置取得能力 ID，校验本地实体、组件、动作空闲与指令；组件缺失时保留模拟 R 回退。
- 恢复全部 50 条战术规则。GL-15 在弹匣加膛内**总弹 ≤2**时进入换弹窗口；余量为 2 时仍有原有点击等待，余量为 1 时立即请求。逐发续装只在弹药增加且动作空闲后继续，防止原生重入。

## 验证边界

前一版仅限 GL-15 空仓的原生原型已获用户实机反馈：日志记录原生请求返回及其后弹药恢复。当前 build 的 Reload 静态表包含全部 50 条战术武器资源 ID；另一把 Rounds 武器的只读组件与能力路径也通过核对。这些证据**不能证明** v0.7.0 在所有武器、两发提前换弹、动作中断或多人场景均可正常工作。原生函数及内存布局仍是版本相关的；后续游戏更新会触发保护性停用，须重新验证。

发布构建经过 62 项 Lua 行为测试、组件表与上下文测试、7 项 Python 测试，以及 8 个 ZIP 的归档、GUID、模式开关和运行时版本核对；离线测试不能替代游戏内验证。

## 安装与测试

关闭游戏，移除旧 Auto Reload 包，在 Mod 管理器中只启用上述一份包，与 Bingus Shared Loader 一起重新部署并重启。使用输入版或原生包的输入回退时，游戏换弹键须为 R。

先测试 GL-15 在总弹 2、1、0 时的请求与实际弹药恢复；再逐类测试 Magazine、Rounds、可更换散热器的 Heat 武器及站桩换弹武器。日志位于 `%LOCALAPPDATA%/CowboyBingus/Helldivers2/Logs/AutoReloadRounds.log`。`START` 行应显示 `revision=auto-reload-0.7.0`（原生包另含 `-native`），`RELOAD_REQUEST sent=true` 只表示输入被接受或原生调用返回，不代表换弹完成。不要公开完整个人日志、游戏 DLL 或内存转储。

源码与离线测试说明见 [README](../README.md)，原生调用证据与限制见 [NATIVE_RELOAD.md](NATIVE_RELOAD.md)。
