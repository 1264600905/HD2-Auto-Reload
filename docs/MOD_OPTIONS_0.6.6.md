# 自动换弹 v0.6.6 菜单设置

与工作区 `ModOptionsMenu-main` 的 API 1 / version 3（Mod Options Menu v1.2）接入。仅自动换弹项目修改，菜单源码无需改动。

## 安装与使用

1. 构建或安装 `build/[普通换弹]Auto-Reload-v0.6.6.zip` 或 `build/[战术换弹]Auto-Reload-v0.6.6-tactical.zip`，替换旧自动换弹包，只启用一份。
2. 同时安装 Mod Options Menu v1.2 和 Bingus Shared Loader v18+，部署并重启游戏。
3. 打开 `Esc → MODS → 自动换弹`，修改选项后点击 APPLY / 应用（键盘 Tab）。未应用的编辑不会影响自动换弹。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 启用战术换弹 | 普通包关闭，战术包开启 | 开启现有武器阈值；关闭后仅真正空仓或已确认烧毁的散热器触发 |
| 换弹延迟（秒） | 0 | 范围 0–5 秒，步进 0.05 秒；从达到换弹条件开始计时 |
| 射击推迟下一次换弹 | 开启 | 在换弹窗口内每次射击从最新射击重新计时；关闭时保留原到期时间 |

已有菜单保存值覆盖包的默认值，普通包与战术包使用同一组选项 ID。设置由 Mod Options Menu 保存到 `%LOCALAPPDATA%/CowboyBingus/Helldivers2/Logs/ModOptionsMenu.values`，重启自动读取。

例如设置延迟 0.5 秒，在进入阈值后 0.3 秒再次射击：开启推迟时约在进入阈值后 0.8 秒请求换弹，关闭时约在 0.5 秒请求。按住鼠标连续射击通过弹药减少识别，不需要松开后重新按下。射击点击也会重置等待，包括空仓后的点击。延迟为 0 时没有额外等待。

菜单延迟覆盖高速武器、0 发阈值和最后一发的旧立即规则，也覆盖散热器更换。站桩武器仍需空仓后新点击射击，从该次点击开始计时；关闭推迟后，在同一次待发送请求期间再次点击不会延长等待。逐发装填等待结束后保留至少 0.1 秒的续装请求间隔。毒矛首次请求遵守设置延迟，之后仍最多补发三次，间隔为原 0.25、0.5、1 秒与设置延迟中的较大值。

修改并应用设置会取消旧待发送请求，按新设置重新观察当前武器。换武器、离开阈值或失去焦点也会清除旧等待。每次发送仍重新校验弹药及身份。

未安装菜单或菜单 API 不兼容时，自动换弹沿用旧构建默认值及点击延迟；注册被拒绝时记录 `OPTIONS_REGISTER_FAILED` 并保留对应默认值。菜单延迟选项注册成功后使用统一计时，其他选项独立注册。

## 验证状态

已通过游戏自带 LuaJIT `lua51.dll` 中的离线测试：控制器计时、站桩延迟触发、持续射击、普通/战术/散热器/载具、设置开关、毒矛有限重试，以及真实 Mod Options Menu 源码的中文分类、滑块步进、保存与重启恢复。输入接口初始化测试只读取 API，不发送按键。

这些检查尚不代表菜单界面和游戏动画的实机验证。建议部署后检查：

1. MODS 中显示“自动换弹”分类及三个中文设置；日志 `START` 版本为 `auto-reload-0.6.6`，`OPTIONS_APPLIED` 与菜单应用值一致。
2. 战术开关关闭时 AR 武器打空触发，开启时沿用原阈值。
3. 延迟 0、0.5、5 秒分别验证首次触发；最后一发和高速武器也遵守非零延迟。
4. 同样的 0.5 秒延迟，分别开启和关闭射击推迟，验证单击、按住持续射击及停止射击后的计时。
5. SG-8 等逐发武器、站桩武器的新空仓点击和毒矛重试均能正确触发；换武器或切出游戏取消旧请求。
6. 修改后应用、退出并重启游戏，确认保存值恢复；未应用编辑退出时仍保留之前的设置。

## 驱逐者实机反馈（2026-10-11）

v0.6.6-debug 的运行记录显示战术换弹开启、菜单延迟 0 秒、射击推迟关闭。GL-15 在进入现有阈值的同一帧发送 R，随后约 5.9 秒才观察到弹药恢复。用户排查后确认是键位问题，并反馈调整键位后已恢复正常。本次保留现有 GL-15 的总弹 ≤2 规则和逐发装填请求行为，没有据此修改武器配置。
