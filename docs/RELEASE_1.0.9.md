安装包：[Auto-Reload-v1.0.9.zip](https://github.com/1264600905/HD2-Auto-Reload/releases/download/v1.0.9/Auto-Reload-v1.0.9.zip)。本地文件：`build/Auto-Reload-v1.0.9.zip`。运行日志版本：`auto-reload-1.0.9`。

**2026-10-18 用户部署实测确认：站桩武器误触发、备弹耗尽后重复请求、切枪后错误换弹三项问题均已修复。**

## 本轮实际问题

用户确认 v1.0.8 的站桩误触发和无备弹请求已修复，切枪串线仍存在。本轮日志中有明确事件：

- `elapsed=574.719`：为 SG-225 实体 970 补发 R，`reason=interrupted_retry`。
- `elapsed=574.750`：上下文变为 P-113 实体 972，同帧已成功发送 R keyup。
- 随后 P-113 从 6 发开始原生装填，备弹 12→11；期间没有为 P-113 发送新的自动 R。

因此，上版脚本请求身份取消和按键释放不足以取消这条实际输入路径。

只读检查当前 build 25480438：Reload 对应 Avatar group 2/action 38，R 的映射使用 Tap 触发；原生处理 `0xaa01f0` 读取该动作。R 的按下和松开可能落在两把武器上，松开后才生成的短按事件会被新武器接收。

## 修改

1. 每帧先读取当前武器、检查原生切枪输入，再执行自有 R 的到期释放。
2. 自有 R 取消时，先通过现有、已校验的通用原生输入消费接口清除 Reload Tap，再安装模式 1 屏蔽，随后发送 keyup。屏蔽有 500 毫秒到期上限；正常情况下经过两个不同的原生输入更新后即主动清除残留并解除。
3. 正常 keyup 后保留该次输入的原武器身份，直到两个原生输入更新经过；这段时间切枪仍能取消未确认的 Tap。使用 Input owner `+0xa7d28` 的原生时钟区分输入更新，避免同一帧的多个 Lua 回调提前解除。
4. 原生切枪输入出现时取消等待中的自动 R、旧重试和开火保护。若该次切枪最终没有发生，已取消的旧请求也不会由定期检查立即重新排队，需重新开火或弹药变化后再判断。

屏蔽仅由本模组尚未完成的自有 R 取消触发，不对每次普通切枪统一屏蔽 R。输入对象变化时不调用旧对象；松键失败保留自有按键所有权并继续释放。

新增原生 Reload Tap 处理代码和相关动作标签签名校验。日志新增：

- `DEBUG_RELOAD_TAP_CANCEL`：清除并屏蔽自有输入对应的原生换弹短按。
- `DEBUG_RELOAD_TAP_DRAINED`：经过原生输入更新后清理完毕。
- `RELOAD_CANCELLED_WEAPON_SWITCH`：原生切枪输入取消旧请求。

## 使用与验证边界

v1.0.8 的站桩触发、备弹读取和停止规则沿用。GUID、设置保存 ID、80–150 毫秒随机换弹等待及开火保护参数沿用。

开发阶段进行了日志分析和运行中游戏的 Python 只读采样、原生代码/绑定读取，没有向游戏写内存、调用游戏函数或生成输入。随后用户部署 v1.0.9 并确认三项问题均已修复；实机结果来自用户反馈，按要求未额外运行自动测试。
